# kintone 汎用カレンダープラグイン

任意の日付/日時フィールドを基準に、kintone の一覧画面ヘッダースペースへ月カレンダーを表示する汎用プラグインです。
PC・モバイル両方に対応し、標準一覧テーブルとの切替、色分け、Google カレンダー連携、祝日表示をサポートします。

## 特長

- **どのアプリにも後付け可能**: 日付／日時フィールドが1つあれば導入でき、アプリの改修は不要です。フィールドコードは設定画面で選択するだけで、ハードコードされたフィールドコードは存在しません。
- **PC・モバイル両対応**: 一覧画面のヘッダースペースにカレンダーを描画するため、カスタムビューを作成できないモバイルでも同じ体験を提供します。
- **標準一覧との切替**: カレンダー表示と標準の一覧テーブル表示をワンクリックで切り替えられます（選択状態は端末に保存されます）。
- **色分け・帯テンプレート**: カテゴリフィールドの選択肢ごとに色を設定でき、帯（イベント）の表示内容も自由にカスタマイズできます。
- **Google カレンダー連携**: 認証不要のテンプレートURL方式で、レコードの予定を Google カレンダーへワンクリックで追加できます。
- **祝日表示**: 日本の祝日（2024〜2030年、内蔵の静的データ）をカレンダーに表示できます。外部APIへの通信は発生しません。
- **参照専用**: 本プラグインはレコードを一切書き込みません。

## 導入手順

1. `npm install` で依存パッケージをインストールします。
2. `npm run build` を実行します。TypeScript の型チェック → テスト → JS/CSS ビルド → `plugin/` へのアセット配置 → `dist/plugin.zip` の生成までが一括で行われます。
   - 初回ビルド時にプラグイン署名用の秘密鍵が無い場合は自動生成され、プロジェクト直下に `private.ppk` として保存されます（`.gitignore` 済みのため誤ってコミットされません）。**このファイルは紛失するとプラグインの更新ができなくなるため、安全な場所に控えてください。**
3. kintone の「カスタマイズ／サービス連携」→「プラグイン」→「読み込む」から `dist/plugin.zip` をアップロードします。
4. 対象アプリの「プラグイン」設定からカレンダープラグインを追加し、以下の「設定項目リファレンス」に従って設定します。
5. アプリを更新（本番反映）すると、一覧画面のヘッダースペースにカレンダーが表示されます。

### 更新版を配布する場合

同じ `private.ppk` を使ってビルドするとプラグイン ID が変わらないため、kintone 側では**上書き更新**として扱われ、**アプリごとの設定値は保持されます**。更新版を出すときは `plugin/manifest.json` の `version` を必ず繰り上げてください。導入先でどのビルドが入っているか判別できなくなります。

## 実機スモークテスト

**単体テストとビルドが通っても、kintone 実環境での動作は保証されません。**（初版ではプラグイン ID の取得方法を誤ったまま「完了」と判断し、実機で一切動作しませんでした。）リリース前に必ず以下を実機で確認してください。

| # | 確認項目 | 合格基準 |
|---|---|---|
| 1 | プラグインのインポートと有効化 | エラーなくアプリに追加できる |
| 2 | 設定画面を開く | 設定フォームと「保存」ボタンが表示される（空白でないこと） |
| 3 | 開始日時フィールドを選んで保存 | 「設定を保存しました」と表示される |
| 4 | 一覧画面を開く | **ブラウザのコンソールにエラーが出ていない**／月カレンダーが描画される |
| 5 | 複数日にまたがるレコード | 開始日から終了日までのバーとして表示される |
| 6 | カテゴリ色分け | 選択肢ごとに設定した色が帯に反映される |
| 7 | カレンダー ⇄ 一覧トグル | 双方向に切り替わり、リロード後も選択状態が保持される |
| 8 | 帯クリック（PC） | ポップオーバーが開き、「レコードを開く」で詳細画面に遷移する |
| 9 | 帯タップ（モバイル） | ポップオーバーを挟まずレコード詳細に直接遷移する |
| 10 | Google カレンダー連携 | レコード詳細画面のボタンから、正しい日時・タイトルで Google の予定作成画面が開く |

確認は PC ブラウザに加えて、**モバイルブラウザと kintone モバイルアプリ内 WebView** でも行ってください。

## 設定項目リファレンス

### 日付マッピング

| 項目 | 説明 |
|---|---|
| 開始日時フィールド（必須） | カレンダー表示の基準となる日付/日時フィールド |
| 終了日時フィールド（任意） | 複数日/複数時間にまたがる予定のバー表示に使用 |

### 帯の表示内容

- **選択リストモード（既定）**: 表示したいフィールドを追加・並べ替えするだけで、内部的にテンプレート文字列（`{フィールドコード}`）へ変換されます。
- **テンプレート文字列モード（詳細設定）**: `{フィールドコード}` 記法で自由にレイアウトできます（例: `{title} / {category}`）。
- PC 用とモバイル用でテンプレートを分けて指定できます（モバイル用が未設定の場合は PC 用にフォールバックします）。

#### テンプレート記法

- `{フィールドコード}` と書くと、そのフィールドの値がプレーンテキストとして展開されます。
- フィールド型ごとに以下のように整形されます。
  - ユーザー／組織／グループ選択: 表示名（複数の場合は「、」区切り）
  - チェックボックス／複数選択: 選択肢を「、」区切りで連結
  - 数値・計算: 桁区切り（例: `1,234,567`）
  - リンク: 値をそのままテキストとして表示
  - その他: 値をそのまま文字列化
- 存在しないフィールドコードを指定した場合は空文字として展開され、設定画面に警告が表示されます。
- 展開結果は常にプレーンテキストとして扱われ、HTML として解釈されることはありません（XSS対策）。

### 色分け

- カテゴリフィールド（ドロップダウン／ラジオボタンを主対象。チェックボックス・複数選択は先頭の値を採用）を選択すると、選択肢が自動的に読み込まれます。
- 選択肢ごとに背景色・文字色を指定できます。未設定の値にはフォールバック色が適用されます。
- コントラストが低い組み合わせ（背景色と文字色の輝度比が3未満）は保存前に警告されます。

### 表示設定

- 週開始曜日（日曜/月曜）
- 祝日表示 ON/OFF
- 1セル最大表示件数（超過分は「他 N件」で折りたたみ表示）
- トグルの既定値（カレンダー/一覧）
- 凡例表示 ON/OFF（モバイルでは折りたたみ表示）

### データ設定

- 追加絞込条件: kintone のクエリ構文の一部を指定できます（例: `ステータス not in ("完了")`）。
- 一覧ビューの絞込条件を引き継ぐ: ON にすると、表示中の一覧ビューの絞込条件も合わせて適用されます（取得できない環境では自動的に無視されます）。

### Google カレンダー連携

- 予定タイトル用テンプレート／説明欄用テンプレート（帯テンプレートと同じ `{フィールドコード}` 記法）
- 場所フィールドの指定（任意）
- 説明欄末尾にレコードへのリンクを自動付与するオプション
- PC は帯クリック時のポップオーバー内、モバイルはレコード詳細画面のヘッダースペースに「Google カレンダーに追加」ボタンが表示されます（PCのレコード詳細画面にも設置されます）。認証不要の URL 遷移方式のため、クリック後は Google 側の画面で保存操作が必要です。

### 設定のエクスポート／インポート

- 設定画面下部からエクスポート（JSON をテキストエリアに表示）／インポート（JSON を貼り付け）ができます。
- インポート時、インポート先アプリに存在しないフィールドコードが含まれる場合は警告として一覧表示されます（保存はブロックされません。除外はユーザー判断に委ねます）。

## リマインダーについて

**本プラグインはリマインダー機能を提供しません。** kintone 標準の「通知」機能（アプリ設定 → 通知 → 条件通知）で、日時フィールドを基準としたリマインダーを設定してください。帯テンプレートには通知用のフィールド（例: 担当者、期限）をそのまま表示できるため、リマインダーの内容確認は本プラグインのカレンダー表示でも行えます。

## 既知の制限

- 1ヶ月あたり100件未満のレコード数を想定した設計です。500件を超える取得が発生した場合は安全のため取得を打ち切り、コンソールに警告を出力します（画面上でエラーにはなりません）。
- カテゴリフィールドとしてチェックボックス／複数選択を指定した場合、色分けには先頭の選択値のみが使用されます。
- 標準一覧テーブルの DOM 構造に依存する箇所（トグル切替）があるため、kintone側の大規模な UI 変更があった場合は動作しないことがあります。その場合はカレンダーと一覧が併置表示されるフォールバック動作となり、機能自体は停止しません。
- 祝日データは2024〜2030年分を内蔵していますが、2027年以降の春分の日・秋分の日・国民の休日等は算出時点の天文計算に基づく予測値です（政府官報での正式決定前の年について）。
- Google カレンダー連携は認証不要のテンプレートURL方式のため、確認画面が一度挟まります（自動登録はできません）。

## 開発者向け情報

```bash
npm install        # 依存パッケージのインストール
npm run typecheck  # 型チェック
npm test           # 単体テスト (vitest)
npm run build      # 型チェック→テスト→ビルド→プラグインzip生成を一括実行
```

- `src/core/` に環境非依存のロジック（設定・データ取得・描画・テンプレート・Google連携・祝日・ユーティリティ）を配置しています。
- `src/adapters/` に PC/モバイルの環境差分（DOM取得・遷移URL・クリック挙動）を集約しています。
- `src/entries/` が実際にビルドされるエントリポイント（desktop / mobile / config）です。
- `plugin/` はビルド成果物を含む配布用ディレクトリで、`npm run build` により `plugin/js/`・`plugin/css/` が生成されます。

### ビルド時アサーション

`scripts/build-plugin.mjs` は、実機でしか露見しない致命的な事故を防ぐため、zip 化の前に以下を検査します。いずれかに違反するとビルドが失敗します。

- **各バンドルに `kintone.$PLUGIN_ID` の参照が残っていること** — プラグイン ID は kintone がプラグイン配下の JS にのみ注入するこの変数から取得します。参照を失うと `kintone.plugin.app.getConfig()` が実行時例外になり、一覧画面も設定画面も停止します。
- **`plugin/config.html` が HTML 断片であること** — 設定画面の HTML は kintone の設定ページ内に挿入されるため、`<!DOCTYPE>` / `<html>` / `<head>` / `<body>` や自前の `<script>` / `<link>` を含めてはいけません。CSS・JS は `manifest.json` の `config` セクションで宣言します。

### プラグイン ID の取り扱い（重要）

`kintone.$PLUGIN_ID` は **スクリプト評価中だけ有効な一時変数**です。kintone は各プラグインの JS を評価した直後にこの変数を破棄するため、`await` を挟んだ後やイベントハンドラの内部から参照しても `undefined` になります。

そのため `src/core/util/pluginId.ts` は **モジュールのトップレベルで同期的に ID を捕捉**し、以降はその値を使い回します。**この捕捉を関数の内部へ移動してはいけません。** 実際に非同期ハンドラ内から参照する実装へ変更したところ、「プラグイン ID を取得できませんでした」で全画面が停止しました。

保険として、`download.do?pluginId=...` 形式のスクリプト URL と、設定画面の URL クエリからも ID を拾えるフォールバックを備えています。この挙動は `test/pluginId.test.ts` の回帰テストで固定されています。
